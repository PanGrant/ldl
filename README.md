# ldl — layout definition language

把「读懂一张桌面 UI 并对它操作」的布局知识，从散落在代码里的谓词和阈值，
变成**声明式定义 + 通用解析装置 + 语料普查验证**三件套。

诞生自 moments-mcp（微信朋友圈自动回复 MCP）的实战：那个项目用
「人假设 → 机器验证 → 照图施工」的方法摸出了一套可靠的感知层，但图纸
（ASCII 文档）和施工（提取函数）同居在一个文件里，漂移靠测试才能抓回。
ldl 是同一方法的通用化：**定义是图纸，实现是施工，两者物理分开**，
一致性靠语料普查钉死，不靠自觉。

## 三层

```
L1 定义层  声明式布局树：container → columns → rows
           每行声明角色 + 高度模型 + 识别契约（什么证据可入座、
           过哪几道结构门、内容是否参与、例外是什么、产出哪些槽位）
           值分两类：窗口几何（每运行实测）∪ 物种习性（语料量定的群体边界）
L2 实现层  measure（首屏量定几何）+ read（照树填座）
           识别函数不再自带门——门从契约声明里来
L3 消费层  动作只引用 schema 槽位，禁止裸像素猜测（消费方自理）
```

## 验证装置

`ldl.census`：对帧语料逐帧运行感知适配器 → 快照；定义或实现任何改动后
重跑 → diff。**除声明允许的变化外零漂移才算过**。快照/语料都在本机
（`local/`，git 忽略）——帧里有真实屏幕内容，永远不进版本库。

## 纪律

- **零第三方依赖**：OCR、像素探针留在消费方，库只吃归一化的行数据和回调。
- **通用性按需生长**：抽象只按真实消费者的需求长，不做 upfront 通用框架。
- **诚实为 None**：感知失败就是 None，绝不瞎判；普查把 None 也当座位记录。
