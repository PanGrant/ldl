# ldl — layout definition language

把「读懂一张桌面 UI 并对它操作」所需的布局知识，从散落在代码里的
谓词和阈值，变成**声明式定义 + 语料普查验证**。

诞生自 moments-mcp（微信朋友圈自动回复 MCP）的实战：那个项目靠
「人假设 → 机器验证 → 按定义实现」的方法做出了可靠的屏幕感知层，
但布局定义和感知实现写在同一个文件里，改动漂移只能靠测试抓。
ldl 把方法提炼成通用库：**定义与实现物理分开，一致性靠语料普查
钉死，不靠自觉**。

## 三层

```
L1 定义层  声明式布局树：container → columns → rows
           每行声明：行角色 + 高度模型 + 识别契约
           值分两类：窗口几何（每运行实测）∪ 语料阈值（语料量定的群体边界）
L2 实现层  measure（首屏量定几何）+ read（照定义识别行、提取数据）
           识别函数不自带阈值——阈值从契约声明里来
L3 消费层  动作只引用 schema 槽位，禁止裸像素猜测（消费方自理）
```

## 术语（一分钟版）

| 术语 | 意思 |
|---|---|
| **LayoutDef** | 一份完整布局定义：app 名 + columns + rows + thresholds + measured |
| **row（行）** | 屏幕上一种横条的身份格。同一类东西（比如"作者名那一行"）是同一种行角色，不管坐进去的是谁 |
| **ColumnSpec** | 一条纵向列的左右界；`MEASURED` = 每运行实测，定义里不许写死 |
| **ContractSpec** | 一行的识别契约。`shape`：认定证据的形状声明；`gates`：要过的位置/结构检查（键指向 thresholds）；`content_blind`：文字内容是否参与判定（默认不参与，False 必须写理由）；`exceptions`：显式声明的例外探针；`emits`：该行认定后产出的槽位名 |
| **thresholds** | 语料阈值表：键 → {value, evidence}。没有证据出处的数字不许入表 |
| **measured** | 实测槽位名单：每次运行现场量的窗口几何，定义只登记名字 |
| **普查 / 快照 / diff** | `ldl.census` 对帧语料逐帧运行感知适配器得快照；任何改动后重跑并对比。除声明允许的变化外零漂移才算过；None↔判定翻转永不豁免，必须人看 |

## 验证装置

`ldl.census`：对帧语料逐帧运行感知适配器 → 快照；定义或实现任何
改动后重跑 → diff。**除声明允许的变化外零漂移才算过**。快照/语料
都在本机（`local/`，git 忽略）——帧里有真实屏幕内容，永远不进版本库。

## 纪律

- **零第三方依赖**：OCR、像素探针留在消费方，库只吃归一化的行数据和回调。
- **通用性按需生长**：抽象只按真实消费者的需求长，不做 upfront 通用框架。
- **诚实为 None**：感知失败就是 None，绝不瞎判；普查把 None 也当作一条独立记录。
